# Public Demo Snapshot Mode

Aletheia supports a cost-aware public demo mode for hosted frontend deployments.

The hosted demo uses real precomputed traces, evaluations, index metadata, dataset samples, qrels, and replay outputs generated by the full local Aletheia pipeline. Expensive live operations like arbitrary retrieval, index rebuilds, reranking jobs, and worker-backed admin jobs are disabled publicly to avoid always-on search and ML infrastructure costs.

This is not fake data. Snapshot JSON is exported from the real local PostgreSQL database after running the full stack with FastAPI, Postgres, Redis/RQ, OpenSearch, Qdrant, embeddings, and reranking.

## Modes

Frontend mode is controlled by:

```text
NEXT_PUBLIC_DEMO_MODE=live
```

Values:

- `live`: use FastAPI through `NEXT_PUBLIC_API_BASE_URL`
- `snapshot`: use static JSON from `apps/web/public/demo-data`

Local development defaults to live mode unless the variable is explicitly set to `snapshot`.

## Generate Snapshot Data

Start the local full stack, run real searches, traces, evaluations, experiments, and replays, then export:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/powershell/export-demo-snapshot.ps1
```

The exporter writes:

```text
apps/web/public/demo-data/
```

Generated files include:

- `manifest.json`
- `overview.json`
- `index-status.json`
- `datasets.json`
- `documents-sample.json`
- `chunks-sample.json`
- `benchmark-queries-sample.json`
- `relevance-judgments-sample.json`
- `search-scenarios.json`
- `traces.json`
- `evaluations.json`
- `experiments.json`
- `replay.json`
- `system.json`

The exporter does not mutate the database and does not require the API server to be running. It reads through the existing SQLAlchemy session configuration.

## Public Deployment

Set this in Vercel for the hosted frontend:

```text
NEXT_PUBLIC_DEMO_MODE=snapshot
```

The frontend can be served for near-zero cost because snapshot files are static. Pages converted to snapshot mode use those files. Pages not yet converted should still show honest unavailable states if no live backend exists.

## What Recruiters Can Use

The public demo can show:

- real query traces
- real retrieval candidates and rank provenance
- real evaluation metrics
- real experiment comparisons
- real index metadata
- real dataset samples and qrels
- real replay outputs

The project remains interview-defensible because every displayed metric or trace comes from the local full pipeline.

## What Is Disabled Publicly

Public snapshot mode should not run:

- arbitrary live retrieval
- index rebuilds
- reranker jobs
- ingestion jobs
- worker-backed admin actions

Those workflows remain available in local live mode.

## Upgrade Path

The snapshot architecture can later be upgraded to a hosted live backend by deploying FastAPI, Redis/RQ, OpenSearch, Qdrant, and the worker, then setting:

```text
NEXT_PUBLIC_DEMO_MODE=live
NEXT_PUBLIC_API_BASE_URL=https://<backend-api-domain>
```

## Atlas Integration Note

Atlas can feed new corpora into Aletheia as datasets. Aletheia then acts as the retrieval, ranking, reranking, evaluation, replay, and search observability layer for those corpora.
