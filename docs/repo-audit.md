# Repository Audit

This document records what belongs in the Aletheia repository, what should stay local, and how to verify release readiness before sharing the GitHub repo broadly.

## Repository Structure Overview

- `apps/web`: Next.js frontend, public snapshot assets, and UI components.
- `services/api`: FastAPI backend, SQLAlchemy models, Alembic migrations, retrieval, indexing, evaluation, replay, benchmark, and export code.
- `services/worker`: worker entry point and worker-oriented service structure.
- `infra`: local infrastructure configuration.
- `data`: small tracked samples and local data placeholders.
- `docs`: technical documentation, diagrams, runbooks, screenshots, and demo planning docs.
- `reports`: tracked report directory markers and documentation, with generated JSON reports ignored by default.
- `scripts`: PowerShell and Python helper scripts.
- `tests`: repository-level test placeholder area.
- `configs`: smoke and benchmark configuration files.

## What Is Committed

- Source code for the frontend, backend, scripts, and tests.
- Technical documentation and runbooks.
- Public snapshot JSON exported from the real local pipeline.
- Screenshot assets captured from the public snapshot demo.
- `.gitkeep` placeholders for intentionally empty directories.
- Small test fixtures.
- README and project documentation.

## What Is Intentionally Not Committed

- Local environment files.
- Secrets, tokens, passwords, and connection strings.
- `node_modules`.
- Next.js `.next` build output.
- Python virtual environments.
- Model caches.
- `ir_datasets` local cache.
- Generated benchmark JSON reports.
- Generated golden smoke JSON reports.
- Large video files unless intentionally selected later.

## Generated And Ignored Artifacts

- `reports/benchmarks/*.json`
- `reports/smoke/*.json`
- `data/models/`
- `data/raw/ir_datasets`
- `.env.local`
- `node_modules/`
- `.next/`
- `services/api/.venv/`
- Python cache folders such as `__pycache__/` and `.pytest_cache/`

## How To Verify

Run:

```powershell
git status --short
powershell -ExecutionPolicy Bypass -File scripts/powershell/doctor.ps1
powershell -ExecutionPolicy Bypass -File scripts/powershell/ci-check.ps1
powershell -ExecutionPolicy Bypass -File scripts/powershell/repo-audit.ps1
```

Useful tracked-file checks:

```powershell
git ls-files | findstr /i ".env.local"
git ls-files | findstr /i "data/models"
git ls-files | findstr /i "node_modules"
git ls-files | findstr /i ".next"
```

No output from these checks is expected for the dangerous local artifact patterns.

## Public Demo Mode Verification

The public demo is a Vercel-hosted snapshot mode. It uses real exported outputs generated by the full local Aletheia pipeline. It does not host the live FastAPI, OpenSearch, Qdrant, Redis, worker, embedding model, or reranker stack publicly.

The public demo must not claim public live arbitrary retrieval. Live retrieval and administrative jobs run in the local full stack.

## No Fake Data Rule

Missing or unavailable values should remain honest. Evaluation metrics must come from real evaluation or benchmark outputs. Snapshot files should be regenerated from the local pipeline, not hand-edited to improve presentation.

## Known Non-Blocking Warnings

- GitHub Actions Node runtime warnings from official actions can appear when upstream actions migrate runtimes.
- Hugging Face unauthenticated warnings can appear in local model workflows if no token is configured.
- Transformer `cache_dir` deprecation warnings can appear from model dependencies.
- Docker images can be large because local ML dependencies are included.

These are non-blocking unless they become validation failures or expose secrets.
