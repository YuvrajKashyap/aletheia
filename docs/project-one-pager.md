# Aletheia One-Pager

## What It Is

Aletheia is a production-style hybrid retrieval, reranking, evaluation, and search observability platform. It compares BM25, dense vector retrieval, hybrid Reciprocal Rank Fusion, and cross-encoder reranking over BEIR SciFact with real query traces, evaluation metrics, index metadata, and replay outputs.

It is not a chatbot or a generic RAG wrapper. It focuses on retrieval infrastructure, ranking quality, evaluation correctness, and operational visibility.

## Why It Exists

Modern retrieval systems need more than a search box. They need reproducible indexing, candidate provenance, evaluation against qrels, trace-level debugging, latency visibility, replay checks, and comparison tools for retrieval modes. Aletheia packages those concerns into a full-stack platform that can be inspected by engineers and technical reviewers.

## Architecture

- Frontend: Next.js, TypeScript, Tailwind CSS, Recharts.
- Backend: FastAPI, Pydantic, SQLAlchemy, Alembic.
- Metadata store: PostgreSQL.
- Async jobs: Redis/RQ.
- Lexical retrieval: OpenSearch BM25.
- Dense retrieval: Qdrant vectors.
- Embeddings: `BAAI/bge-small-en-v1.5`.
- Reranker: `cross-encoder/ms-marco-MiniLM-L-6-v2`.
- Public demo: Vercel snapshot mode using real exported local outputs.

## Retrieval Modes

- `bm25`: lexical retrieval through OpenSearch.
- `dense`: vector retrieval through Qdrant.
- `hybrid`: rank-based Reciprocal Rank Fusion over BM25 and dense candidates.
- `hybrid_rerank`: hybrid candidates rescored by a cross-encoder reranker.

## Evaluation Methodology

Aletheia evaluates BEIR SciFact with 5,183 documents, 300 benchmark queries, and 339 qrels. SciFact qrels are document-level, while Aletheia retrieves chunks, so evaluation maps chunk hits back to parent document IDs and deduplicates before scoring.

Metrics include Recall@5, Recall@10, MRR@10, NDCG@10, average latency, p50 latency, and p95 latency. Metrics come from real evaluation runs, not browser-side estimates.

## Public Demo Mode

Public demo: https://aletheia.yuvrajkashyap.com

The hosted demo is snapshot-backed. It uses real precomputed outputs generated by the full local Aletheia pipeline. Live arbitrary retrieval, reranking, index rebuilds, evaluation jobs, replay jobs, and admin actions are disabled publicly to avoid always-on OpenSearch, Qdrant, Redis, worker, and ML model hosting costs.

The full live stack runs locally through Docker Compose and local Python/Node processes.

## Benchmark Summary

The full 300-query SciFact runs cover BM25, dense, and hybrid RRF. Hybrid RRF achieved the strongest full-run Recall@10 in the recorded benchmark table. BM25 remained fastest. Dense and hybrid runs are slower because they include local embedding model calls. The hybrid rerank row is a 50-query sampled CPU rerank benchmark and is not directly comparable to the full 300-query runs.

See `docs/benchmark-results.md` for methodology and reproduction details.

## Technical Highlights

- Versioned index lifecycle with explicit activation and rollback.
- Async job orchestration for ingestion, indexing, evaluation, experiment comparison, and replay.
- Query traces with candidate provenance across lexical, dense, fusion, and rerank stages.
- Document-level qrels evaluation correctness for chunk-based retrieval.
- Experiment matrix comparing retrieval modes across real runs.
- Replay harness for saved and golden queries.
- Public snapshot mode that stays honest without hosting a full search/ML stack.
- CI, doctor checks, repo audit script, screenshots, diagrams, and release readiness docs.
